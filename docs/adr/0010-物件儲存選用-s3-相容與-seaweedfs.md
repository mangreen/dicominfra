# ADR 0010：物件儲存採 S3 相容 API，本機與 CI 使用 SeaweedFS

- 狀態：已接受（2026-11-24，使用者授權由 Claude 依準則決定）
- 範圍：影像檔（原始與去識別化後）的物件儲存

## 背景

準則：整個 PoC 要能在這台開發機完整跑通；不綁定任何公有雲；未來地端與雲端都能部署；PoC 要精簡方便。
流程採用預簽名 URL 讓客戶端直傳影像，影像不經過 API（見 `docs/architecture.md`）。

## 選項

| 選項 | 評估 |
|---|---|
| **SeaweedFS（`weed mini`）** | Apache 2.0；單一指令或單一容器啟動，可用環境變數預建憑證與 bucket；支援預簽名 URL；可用於單機也可擴充 |
| MinIO 社群版 | **不選。** 2025 年 10 月起停止發佈 Docker 映像與預編譯二進位，2025 年 12 月進入維護模式，2026 年 2 月儲存庫被封存；新專案不適合作為預設 |
| Garage | AGPLv3；偏輕量自架，S3 功能完整度較低；需要先設定叢集配置，PoC 不夠精簡 |
| RustFS | Apache 2.0，但有來源評為仍在 alpha 階段 |
| Ceph RGW | 成熟但太重，不適合這台開發機 |
| 本機檔案系統 | 不是真實的物件儲存，沒有預簽名語意，也違反「測試用真實基礎設施」的規則 |

## 決定

1. 應用程式只依賴 **S3 API**（SigV4、path-style、預簽名 URL），透過 `ObjectStore` Port 與 `S3ObjectStore` adapter 使用（ADR 0009）。
2. 本機與 CI 使用 **SeaweedFS**。S3 API 是事實標準，雲端與多數地端儲存都能接上，所以不綁定任何公有雲；
   地端可沿用 SeaweedFS，或換成其他 S3 相容儲存，只改設定。
3. 客戶端函式庫使用 **boto3**（同步，以 `asyncio.to_thread` 包裝；預簽名只是本地計算）。之後要換 `aiobotocore` 或其他函式庫，只改 adapter。
4. 以 GCS 原生 API 或其他非 S3 儲存為目標時，另寫 adapter；本 ADR 沒有驗證這些。

## 已驗證（沙箱，Linux，SeaweedFS 4.55，boto3）

預簽名 PUT 上傳 512 KB 成功；HEAD 確認大小一致；預簽名 GET 下載後 SHA-256 一致；簽名被竄改的請求被拒；過期的預簽名連結被拒；錯誤憑證被拒；刪除後物件不存在。
常駐記憶體約 130 MB。

**未驗證：** 在你的 Mac 與 Docker Desktop 4.12 上執行；Docker 映像標籤（M2 加入 Compose 時釘住並以 `make up` 驗證）；大檔的 multipart 上傳；生命週期與保存期限規則；雲端 S3／GCS 的 adapter。

## 實作時要注意（M2）

- **預簽名 URL 的主機名稱是簽名的一部分。** 客戶端實際連線的位址必須與簽名時使用的位址相同，所以要分成「內部端點」與「對外端點」兩個設定；容器內的 API 與主機上的客戶端看到的位址不同。
- **安全：** `weed mini` 啟動時會警告 filer 的 IAM gRPC 服務預設沒有驗證，任何連得到該埠的人都能建立使用者與政策；不提供憑證時還會允許匿名存取。
  Compose 只對外開 S3 埠且綁定 `127.0.0.1`，不開 filer、gRPC 與管理介面的埠，並且一定設定憑證。
- `weed mini` 是為開發與單機設計；`weed server` 才是為正式環境設計，正式部署需要另外評估並設定。
- `weed mini` 會把 S3 綁在偵測到的主機 IP，在容器裡經埠對映使用不受影響。
- region 會被忽略，但 SDK 需要一個非空值。

## 後果

- 本機開發不需要任何雲端帳號。
- 預簽名直傳讓影像不經過 API，但增加了端點設定的複雜度。
- 若要成案，需要為正式環境重新評估儲存系統的容量、耐久性與維運，不能只沿用 `weed mini`。
