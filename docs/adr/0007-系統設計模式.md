# ADR 0007：採用的設計模式與刻意不採用的模式

- 狀態：已接受（2026-11-24，經使用者確認）
- 範圍：PoC 後端與 Agent 邊界使用的設計模式

## 原則

每個模式都要對應一個具體問題與一個驗證它的測試；沒有實際效益的抽象不引入。

## 採用的模式

| 類別 | 模式 | 解決什麼問題 | 用在哪裡 | 如何驗證 |
|---|---|---|---|---|
| 架構 | Modular Monolith，多個進程入口 | 邊界清楚且部署簡單 | 整體（ADR 0001） | review；必要時加依賴方向檢查 |
| 架構 | Service Layer（應用服務） | 授權與交易邊界集中，REST 與 MCP 共用同一條路徑 | 各模組 | 整合測試 |
| 架構 | Ports & Adapters，**只用在外部邊界** | 隔離不可控、可替換的依賴 | MessageBus、推論平台 client、計費 client、物件儲存 | 假服務與契約測試 |
| 架構 | Anti-Corruption Layer | 外部契約改變不外溢到核心模型 | 推論契約轉換（ADR 0005） | 契約測試 |
| 資料 | Transactional Outbox | 狀態與訊息原子寫入，不遺失 | 案件到 RabbitMQ（ADR 0002） | relay 中途當機的故障注入 |
| 資料 | Idempotent Consumer（inbox 去重） | at-least-once 下不重複副作用 | Worker | 同一訊息重送測試 |
| 資料 | 條件式 UPDATE（compare-and-set）加唯一約束 | 併發下不覆蓋、不重複 | 狀態機、收件 | Barrier 併發測試（M0 已有雛形） |
| 資料 | Append-only Ledger | 用量可稽核、可對帳 | `usage_events`（ADR 0008） | 計費故障注入與對帳測試 |
| 資料 | Row-Level Security（共用 schema 加 tenant_id） | 租戶隔離的最後防線 | M1 | 跨租戶與連線池殘留測試 |
| 資料 | Expand-and-Contract | 不中斷服務的 schema 演進 | Migration | 新舊版本共存測試 |
| 可靠性 | 重試加指數退避加抖動；DLQ；Watchdog（Sweeper） | 暫時性故障自癒，永久失敗可人工處理 | Worker、relay、Billing reporter | 故障注入 |
| 可靠性 | Circuit Breaker、逐層逾時、Bulkhead | 外部故障不拖垮自己 | 推論與計費 client | 假服務注入逾時與 5xx |
| 可靠性 | Competing Consumers、Queue-Based Load Leveling | 水平擴展與削峰 | Worker | 多 worker 併發測試 |
| 可靠性 | Asynchronous Request-Reply（202 加任務編號） | 長任務不佔用連線 | API、MCP 工具 | 整合測試 |
| Agent | Thin Adapter（MCP server）加 Token Exchange | 單一授權路徑，不轉傳 token | M5a（ADR 0004） | 越權情境測試 |
| Agent | Propose–Approve（人類核准寫入） | 即使 Agent 被誘導也無法替使用者核准 | MCP 寫入工具 | injection 情境測試 |
| Agent | Strategy 加 Fallback Chain | LLM 供應商可替換，離線降級為規則模式 | Agent 專案 | fake LLM |
| 觀測 | Trace Context 傳遞加結構化日誌 | 跨進程追蹤同一個請求 | HTTP 與訊息 header | M6 端到端追蹤 |

## 刻意不採用

| 模式 | 為什麼不用 | 何時重新評估 |
|---|---|---|
| 微服務 | 分散式成本高於 PoC 的收益 | 需要獨立部署或擴展某個模組 |
| CQRS、Event Sourcing | 讀寫需求單純；用 outbox 與帳本已足夠 | 需要完整事件重播或稽核重建 |
| Saga／協調器 | 流程是線性的，只有一個外部步驟；補償以狀態轉移與重試表達 | 出現多個需要補償的外部步驟 |
| DDD 聚合、通用 Repository | 以工作流程與狀態機為主，抽象不帶來效益；查詢由各模組自己擁有 | 領域規則明顯變複雜 |
| Kafka、Service Mesh | 見 ADR 0002；PoC 規模用不到 | 見 ADR 0002 |

## 後果

- 模式較多，每一項都需要對應的測試，否則只是文件上的設計。
- 「Ports & Adapters 只用在外部邊界」需要在 review 時守住，避免抽象擴散。
