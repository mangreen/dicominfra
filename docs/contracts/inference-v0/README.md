# 推論契約 v0.1（草案）

**狀態：草案，尚未經 DS 團隊審閱。** 這是 PoC 用的通用假契約：影像模態與模型輸出都還沒有定義，
所以這裡只描述「送出什麼、回來什麼、結果如何表示」的最小骨架，供雙方討論後修改。

- 請求：[`request.schema.json`](request.schema.json)
- 結果：[`result.schema.json`](result.schema.json)
- 範例：[`examples/`](examples/)
- 測試：`tests/contract/`（範例必須通過 schema，常見錯誤輸入必須被拒絕）

## 已定下的設計選擇（可討論）

| 選擇 | 理由 |
|---|---|
| `request_id` 是冪等鍵，同一個 ID 重送必須得到同一個結果 | 訊息會重送，不能重複執行或重複計費 |
| 測量值用十進位字串，單位用 UCUM | 避免浮點誤差；報告數字的正確性是後端的責任 |
| `status` 為 `succeeded` 時一定有 `measurements`、不可有 `error`，`failed` 則相反 | 讓結果只有一種合法的解讀 |
| `error.retryable` 由平台明確指出 | 我方只重試可以安全重試的失敗 |
| 輸入只傳已去識別化的物件參照與 SHA-256 | 契約中不出現任何病患資訊 |
| `additionalProperties: false` | 避免雙方對欄位的理解悄悄偏離 |

## 需要 DS 團隊回答的問題

1. 影像模態有哪些？每個模態的模型輸出是否不同？
2. 輸出只有數值測量嗎？有沒有幾何結果（輪廓、座標、遮罩）？座標系統與單位如何定義？
3. 錯誤碼清單與哪些是可重試的？
4. 平台對 `request_id` 的去重視窗有多長？
5. 結果用回呼還是輪詢取得？預期的處理時間與逾時上限是多少？
6. 模型版本更新時，舊結果是否需要保留重算的能力？
7. 單次請求的檔案數量與大小上限。
